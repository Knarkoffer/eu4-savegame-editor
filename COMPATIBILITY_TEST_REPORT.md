# Savegame compatibility test report

Audit completed on 2026-09-14. The modernized editor produced **zero savegame
output mismatches** against the untouched original in 12,845 paired
comparisons. Every generated `.eu4` file was compared as raw bytes and by
SHA-256 checksum.

## Compared versions

- Original commit: `3df1ed2a224eca00f1ac5feb768daf7744a3f48c`
- Original source SHA-256:
  `8ffddaf6208c4740f43972b136bbc4881572207e61bdcf5b592264627feb5212`
- Modernized source SHA-256:
  `4ea9269ed11e7f99ec8183cecb1bdbb07ec29f4d941c1c0e919b22c1ea461038`
- Runtime: native 64-bit Windows Python 3.13.5, UTF-8 mode disabled, cp1252
  locale

The original and modernized programs ran against separate copies of each
input. Final manifest verification confirmed that all 21 source inputs and both
source snapshots remained unchanged.

An additional 18 fresh-process spot checks covered the repaired edge cases and
CLI-only behavior. All 18 had the same save-output outcome and matching bytes
when an output file existed. This brings the audit to 12,845 paired comparisons
and 25,690 editor executions.

The synthetic matrix covered eight individual edit flags plus `--all` and
`--verbose`. Fixtures exercised LF, CRLF, CR, mixed endings, no final newline,
quoted cultures, missing culture data, extra monarch-point tokens, values over
the maximum, and values that were already maximized. The 208 cases repeated
after the paused run were deduplicated by source and case; their classifications
and output hashes were consistent.

## Compatibility fixes verified

The audit found and verified fixes for three transformation regressions:

- Province cultures enclosed in quotes now follow the original matching and
  replacement behavior.
- Monarch-point lines with an extra token now retain the original script's
  replacement behavior.
- An invalid gold value is ignored when another edit is selected, while
  `--all` still supplies the original all-edits gold value.

Six byte-exact golden outputs generated by the original source are retained in
`tests/fixtures/`, with provenance and SHA-256 checksums. Fourteen permanent
unit and characterization tests pass on Linux and native Windows Python.

## Known command-line differences

Nine batch cases differed only in process exit status. They all used a
deliberately incomplete, header-only input: the original sometimes returned
success without creating output, while the modernized editor reported the
missing primary culture. Both programs created no output in every such case.

Four of the 18 direct checks also differed only in exit status:

- Invalid gold with no other edit: original 1, modernized 2.
- No edit flags: original 1, modernized 2.
- `--verbose` without an edit: original 1, modernized 2.
- `--version`: rejected by the original with 2, supported by the modernized
  editor with 0.

Help and diagnostic text also differ because the command-line interface was
modernized. These differences do not change `.eu4` output.

## Evidence and privacy checks

Detailed JSONL records, source snapshots, input manifests, hashes, and direct
subprocess artifacts are retained under the Git-ignored
`.compatibility-audit/2026-09-13/` directory. Representative save data is not
tracked.

The privacy scan checked the nonignored working tree, including hidden files,
and separately inspected the content and paths of every Git object reachable
from all local refs. Neither scan found the configured private-name or employer
terms. A normal `rg` working-tree search alone does not inspect Git history,
ignored files, unreachable objects, or reflog-only history.

## Limits

This is characterization evidence for the tested inputs, flag combinations,
argument forms, encodings, and line-ending variants. It cannot prove equivalent
behavior for every possible malformed or future save format. Any later change
to transformation code requires rerunning the permanent tests and the affected
binary-comparison phases.
